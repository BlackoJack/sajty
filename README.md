# Сайты для небольших дел — лендинг

**Живёт здесь: https://blackojack.github.io/sajty/**

Одностраничник, который продаёт сайты небольшому бизнесу: визитка, каталог, лендинг. Тот же визуальный язык, что у рекламных карточек и сайта-визитки инженера: бумага `#F1EEE7`, чернила `#111214`, лайм `#C6F24E`, Unbounded + Onest + JetBrains Mono.

Astro 7 + Tailwind 4, статика, JS только на интерактиве.

## Запуск

```bash
npm install
npm run dev         # http://localhost:4321
npm run admin:dev   # локальный API на 127.0.0.1:8787, пароль local-admin
npm test
npm run build       # статика в dist/
```

Админка на http://localhost:4321/admin. `npm run dev` сам ходит в локальный API. Без `admin:dev` страница открывается, а сохранение заявок ждёт облако.

## Что где менять

**Админка** `/admin` — имя, контакты, цены, три позиции и ссылка на живой пример. Эти значения в репозиторий не коммитятся: их хранит админка. Пока API не ответил, на странице запасные цены из `yandex/lead/content.default.json`, а кнопки контактов скрыты.

**`src/config.ts`** — только форма и текст для поиска: `meta.title`, `meta.description`. Домен задаётся в `astro.config.mjs` (`SITE_URL`).

**Тексты** — `src/data/content.ts` (зачем сайт, кому подойдёт, что входит, шаги, гарантии, FAQ). Названия трёх типов правятся в админке.

**Визуал** — `src/styles/global.css`: палитра и шрифты в блоке `@theme`.

## Секции

1. Hero — заголовок, цены-факты, интерактивный мокап (переключение визитка/каталог/лендинг).
2. «Зачем это вам» — четыре причины + честная сноска, что сайт не заменяет рекламу.
3. «Что я делаю» — три типа сайтов с ценами и что входит в любую работу.
4. Калькулятор — тип сайта + доплаты, итог считается сразу, кнопка собирает готовый текст заявки.
5. Как проходит работа — четыре шага и четыре гарантии.
6. Примеры — реальный сайт (скриншот) и два демо-макета.
7. FAQ — восемь вопросов, включая «кому не подойдёт».
8. Контакты — Telegram, почта, форма.

## Форма

`POST /api/lead`. Два обработчика с одной и той же проверкой:

- Cloudflare Pages — `functions/api/lead.ts`
- Yandex Cloud — `yandex/lead/index.js`, выкладка `npm run deploy:yandex`

Заявка пишется в закрытый бакет и получает номер вида С-1001. В админке у неё статус (новая, в работе, завершена, отменена) и отдельная заметка. Письмо уходит по SMTP, который задаётся на `/admin` (для Gmail — пароль приложения, сервер `smtp.gmail.com`, порт 465). Токен бота и chat id тоже правятся там и на сайт не отдаются. Telegram из облака Яндекса по-прежнему может не открыться: заявка всё равно сохраняется, а в админке видно, ушло ли письмо.

Пустой контакт в админке прячет кнопку на сайте. Форма перед отправкой берёт короткий жетон с `GET /api/guard`: слишком быстрый повтор и пачка заявок с одного адреса останавливаются без капчи. Окна для гостей правятся на `/admin`: взятая скидка или подарок записываются в заявку.

## Публикация

- **Yandex Cloud**: `npm run deploy:yandex` — статика в Object Storage, заявка в Cloud Functions, оба на одном API Gateway. Перед этим `yc init`, платёжный аккаунт на каталоге и заполненный `.env`.
- **Cloudflare Pages**: build `npm run build`, output `dist`, папка `functions/` подхватывается сама. Для посетителей из России этот вариант сейчас ненадёжен.
- **Свой сервер/кластер**: отдать `dist/` через nginx (см. пример в README основного сайта).

## Публикация

Готовы оба варианта — выбирайте, где удобнее.

### GitHub Pages

1. Создать репозиторий, запушить: `git remote add origin git@github.com:USER/REPO.git && git push -u origin main`.
2. **Settings → Pages → Source: GitHub Actions** (это важно, иначе Pages будет искать Jekyll).
3. Дальше пуш в `main` или `master` запускает `.github/workflows/deploy.yml`. Один шаг публикует
   статику на GitHub Pages, второй выкладывает сайт и функцию заявки в Яндекс. Адрес Pages workflow
   берёт из `configure-pages`, поэтому `SITE_URL` и `BASE_PATH` руками заполнять не нужно.
4. Для Яндекса в секретах репозитория нужны `YC_SA_JSON`, `YC_FOLDER_ID`, `YC_LEAD_KEY`
   и `ADMIN_PASSWORD`. `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` необязательны: после первого
   сохранения их хранит админка. Секреты записывает `bash scripts/github-secrets.sh` после
   `gh auth login`. Без обязательных секретов Pages всё равно выйдет, а шаг Яндекса остановится
   с именем недостающего секрета.
5. Сайт на GitHub будет на `https://USER.github.io/REPO/`. Рабочая форма и админка живут на адресе Яндекса.

### GitLab Pages

1. Запушить репозиторий в GitLab (страница Pages включается сама, когда появляется джоба `pages`).
2. `.gitlab-ci.yml` соберёт сайт и положит его в `public/` — этого GitLab и ждёт.
3. Адрес и подпапка считаются из `CI_PAGES_URL`, руками ничего задавать не нужно.

### Свой домен или сервер

```bash
npm run build          # dist/ — обычная корневая версия
```

Для подпапки (например, `https://example.com/sites/`):

```bash
SITE_URL=https://example.com BASE_PATH=/sites/ npm run build
```

`SITE_URL` и `BASE_PATH` читаются в `astro.config.mjs`; все ссылки на картинки и демо-страницы
идут через `asset()` из `src/config.ts`, поэтому переносятся вместе с базой.

## Демо-примеры

В блоке «Как это выглядит» лежат два демо-сайта — чтобы было что показать до появления
первых клиентов. Это настоящие страницы, их можно открыть:

- `public/demo/manicure.html` — визитка студии маникюра, `public/demo-manicure.png` — скриншот.
- `public/demo/auto.html` — каталог автосервиса, `public/demo-auto.png` — скриншот.

Подписаны как «демо-пример», а не «кейс клиента» — это честно и не разваливается на первом созвоне.
Когда появится первый реальный клиент: положите его скриншот в `public/`, замените первый блок
в `src/components/Examples.astro`.

## Что ещё внутри
